

# 报销单校验与汇总工具 用户手册

## 一、工具简介

**expense-reporter** 是一款纯标准库实现的命令行工具，用于自动处理员工报销记录的校验、去重、限额比对与汇总报表生成。

- **目标用户**：行政专员（批量导入、获取异常清单与汇总报表）、财务复核人员（依据报表与异常清单做人工复核）
- **技术约束**：纯 Python 标准库，不引入第三方依赖；金额计算使用 `Decimal`；不访问网络，完全离线运行
- **交付位置**：`workspace/expense-reporter/`

---

## 二、快速上手

### 2.1 环境要求

- Python 3.8 及以上
- 无需安装任何第三方包

### 2.2 首次运行

```bash
# 进入项目目录
cd workspace/expense-reporter

# 查看帮助信息
python -m expense_reporter --help
```

### 2.3 基本调用格式

```bash
python -m expense_reporter <input.csv> [--config limits.json] [--report report.md] [--json report.json] [--max-age-days 365]
```

| 参数 | 说明 | 是否必填 |
|------|------|----------|
| `<input.csv>` | 报销记录 CSV 文件路径 | **必须** |
| `--config` | 类别月度限额配置文件（JSON 格式） | 可选 |
| `--report` | Markdown 汇总报表输出路径 | 可选 |
| `--json` | JSON 机器可读输出路径 | 可选 |
| `--max-age-days` | 日期有效范围（默认 365 天） | 可选 |

### 2.4 退出码说明

| 退出码 | 含义 |
|--------|------|
| `0` | 正常完成，无任何异常记录（无解析错误、无异常、无重复、无超限） |
| `1` | 完成处理，但存在解析错误、异常、重复或超限记录 |
| `2` | 输入错误（输入文件不存在、必需列缺失、参数非法） |

## 三、输入文件格式

### 3.1 CSV 文件规范

**编码要求**：UTF-8（带或不带 BOM 均可）

**必需列（顺序固定）**：

| 列名 | 说明 | 示例 |
|------|------|------|
| `date` | 报销日期，格式 YYYY-MM-DD | `2025-03-15` |
| `employee` | 员工姓名 | `张三` |
| `category` | 报销类别 | `travel`、`meal`、`office`、`other` |
| `amount` | 报销金额，两位小数 | `128.50` |
| `currency` | 币种，固定为 `CNY` | `CNY` |
| `note` | 备注信息（非空） | `高铁票` |

**允许多余列**：表头后如有多余列会被自动忽略，不影响解析。

**坏行处理**：字段数不符或缺少必需列的行记入解析错误清单，包含行号与原因，**不中断**其余行的处理。

#### 示例 CSV（`expenses.csv`）

```csv
date,employee,category,amount,currency,note
2025-03-01,张三,travel,580.00,CNY,北京至上海高铁
2025-03-02,李四,meal,45.50,CNY,业务招待餐
2025-03-03,张三,office,128.00,CNY,办公用品
2025-03-01,张三,travel,580.00,CNY,北京至上海高铁
2025-03-15,王五,travel,1200.00,CNY,出差机票
```

### 3.2 限额配置文件（JSON）

**文件格式**：JSON，键为类别名，值为该类别每月金额上限（元）。

#### 示例配置（`limits.json`）

```json
{
  "travel": 3000.00,
  "meal": 2000.00,
  "office": 1000.00
}
```

**说明**：
- 未提供 `--config` 或配置中缺少某类别时，该类别不做限额校验，报告中注明「未设限」
- 限额按「员工 × 类别 × 月份」独立计算，跨月不累计

## 四、功能操作指南

### 4.1 执行校验与汇总

#### 场景一：基础校验（无限额配置）

```bash
python -m expense_reporter expenses.csv --report report.md
```

**输出**：生成 Markdown 报表 `report.md`，包含统计汇总与各清单。

#### 场景二：带限额配置的完整校验

```bash
python -m expense_reporter expenses.csv --config limits.json --report report.md --json report.json
```

**输出**：同时生成 Markdown 报表与 JSON 机器可读文件。

#### 场景三：自定义日期范围

```bash
python -m expense_reporter expenses.csv --config limits.json --max-age-days 90
```

**说明**：仅处理最近 90 天内的报销记录，早于此范围的记录记为异常。

---

### 4.2 理解输出报表

#### 4.2.1 Markdown 报表结构

报告包含以下部分：

1. **报表头**：统计口径说明、生成时间、输入文件名、总行数
2. **汇总维度**：
   - 按员工汇总：各员工有效金额合计与笔数
   - 按类别汇总：各类别有效金额合计与笔数
   - 按月份汇总：各月有效金额合计与笔数
3. **明细附录**：
   - 解析错误清单：含行号与错误原因
   - 异常清单：含行号、违反规则与原始字段值
   - 重复清单：同批次内重复记录
   - 超限清单：超出月度限额的记录

**金额格式**：所有金额均为两位小数。

**无清单时**：显示「无」。

#### 4.2.2 JSON 输出结构（`--json` 参数）

```json
{
  "summary": {
    "by_employee": {...},
    "by_category": {...},
    "by_month": {...}
  },
  "anomalies": [...],
  "duplicates": [...],
  "over_limit": [...],
  "parse_errors": [...]
}
```

**注意**：所有金额以字符串表示（两位小数），不使用浮点数。

---

### 4.3 校验规则说明

每条有效解析的记录依次校验以下规则，任何一条不满足即记入异常清单：

| 规则编号 | 规则内容 | 违规示例 |
|----------|----------|----------|
| R1 | `amount` 大于 0 | `amount = 0` 或负数 |
| R2 | `date` 不晚于当天，且不早于 `--max-age-days` 天前 | 日期过期或未来日期 |
| R3 | `category` 属于 `travel`、`meal`、`office`、`other` | 未知类别如 `entertainment` |
| R4 | `note` 非空（去空白后） | 空备注 |
| R5 | `currency` 为 CNY | 其他币种 |

**多条违规**：同一条记录命中多条规则时，逐条列出。

---

### 4.4 重复报销检测

**判定标准**：同一员工、同一类别、同一金额、同一日期的记录视为重复。

**处理逻辑**：
- 同一批次内第二次及之后出现的行标记为「重复」
- 第一次出现保留为有效记录
- 重复检测在校验之后进行，仅针对未被判定为异常的记录
- **检测范围仅限同一次导入批次内部**，不与历史文件比对

---

### 4.5 类别月度限额校验

**计算方式**：按「员工 × 类别 × 月份」聚合有效记录金额，超出上限的记录按时间顺序标记为「超限」，直至该员工该类别当月剩余额度用尽。

**示例**：
- 限额配置：`travel` 每月上限 3000 元
- 员工 A 3 月报销：1500 + 1200 + 800 = 3500 元
- 结果：前两条（2700 元）有效，第三条（800 元）超限

**未设限说明**：未提供 `--config` 或配置中缺少某类别时，该部分不做限额校验，报告中注明「未设限」。

## 六、常见问题 FAQ

### Q1：CSV 文件缺少某些列会怎样？

**A**：必需列为 `date`、`employee`、`category`、`amount`、`currency`、`note`。缺少必需列的行将记入解析错误清单，包含行号与原因，不会中断其余行的处理。

### Q2：金额格式有什么要求？

**A**：`amount` 字段必须为两位小数金额字符串（如 `128.50`）。工具内部使用 `Decimal` 计算，避免浮点精度误差。

### Q3：重复记录如何判定？

**A**：同一员工、同一类别、同一金额、同一日期的记录视为重复。同一批次内第二次及之后出现的行标记为「重复」，第一次出现保留为有效记录。

### Q4：限额配置文件中未包含某个类别怎么办？

**A**：未提供 `--config` 或配置中缺少某类别时，该类别不做限额校验，报告中注明「未设限」。

### Q5：日期范围如何控制？

**A**：使用 `--max-age-days` 参数指定天数（默认 365 天）。`date` 必须不晚于当天，且不早于指定天数之前。

### Q6：如何查看详细的校验失败原因？

**A**：异常清单中会注明行号、违反的规则编号（R1-R5）与原始字段值。例如：`R1: amount=0 不大于0`。

### Q7：JSON 输出与 Markdown 报表内容是否一致？

**A**：是的，两者内容完全一致，JSON 中所有金额字段均为字符串类型（两位小数）。

### Q8：处理大量数据时性能如何？

**A**：工具设计目标为 10,000 行合法记录在 30 秒内完成全部校验、去重与报表输出。

### Q9：支持哪些操作系统？

**A**：只要安装 Python 3.8+ 即可运行，支持 Windows、macOS、Linux 等主流操作系统。

### Q10：能否处理带 BOM 的 UTF-8 文件？

**A**：可以。工具自动识别并正确处理带 BOM 或不带 BOM 的 UTF-8 编码文件。
