## 一、功能简介

`expense_reporter` 是一个纯 Python 标准库实现的命令行工具，用于批量校验员工提交的报销记录 CSV，并自动生成 Markdown 汇总报表（可选 JSON 机器可读输出）。

| 单条记录校验（金额、日期、类别、备注、币种） | REQ-002 | ✅ 已完成 |
| 重复报销检测 | REQ-003 | ⏳ 开发中 |

> **说明**：本手册后续章节基于需求规格与已完成模块的测试证据编写。标记"开发中"的功能，其 CLI 参数与行为与需求规格一致，待模块完成后即可启用。

## 二、快速上手

### 2.1 环境要求

- Python 3.8+（仅使用标准库，无需 `pip install`）
- 操作系统：Windows / macOS / Linux 均可

### 2.2 目录结构

交付物位于 `workspace/expense-reporter/`：

```
workspace/
└── expense-reporter/
    ├── expense_reporter/
    │   ├── __init__.py
    │   ├── cli.py              # 命令行入口（开发中）
    │   ├── csv_parser.py       # CSV 解析模块
    │   ├── validator.py        # 单条记录校验模块
    │   ├── models.py           # 数据模型
    │   └── ...                 # 其他模块（开发中）
    ├── tests/
    │   ├── test_csv_parser.py  # 14 项测试全覆盖
    │   └── test_validator.py   # 26 项测试全覆盖
    └── README.md
```

### 2.3 运行工具

```bash
python -m expense_reporter input.csv --report report.md
```

> 若 `input.csv` 文件不存在或格式非法，工具将输出错误信息并以退出码 `2` 终止；若解析/校验发现异常记录，以退出码 `1` 终止；全部通过则以退出码 `0` 终止。

## 三、功能详解与操作示例

### 3.1 CSV 输入格式（REQ-001）

报销记录 CSV 文件需满足以下要求：

- **编码**：UTF-8（支持 BOM，带/不带均可）
- **首行**：表头，必需列依次为 `date`、`employee`、`category`、`amount`、`currency`、`note`
- **多余列**：允许存在，将被直接忽略，不参与任何校验
- **坏行处理**：字段数不符或缺少必需列时，该行记入**解析错误清单**，不中断其余行的处理

#### 样例 CSV

```csv
date,employee,category,amount,currency,note
2025-03-01,张三,travel,1250.00,CNY,出差机票
2025-03-02,李四,meal,85.50,CNY,客户餐费
2025-03-03,王五,office,320.00,CNY,办公用品
```

#### 测试证据：坏行解析

测试用例 `test_csv_parser.py` 覆盖了以下场景，均通过（共 14 项）：

| 场景 | 预期结果 | 结果 |
|------|----------|------|
| 好行解析 | 正常进入 records 列表 | ✅ |
| BOM 头处理 | 正确识别表头 | ✅ |
| 多余列忽略 | 不影响解析 | ✅ |
| 坏日期（格式错误） | 记入 ParseError，含行号与原因 | ✅ |
| 坏金额（非两位小数） | 记入 ParseError | ✅ |
| 坏币种（非 CNY） | 记入 ParseError | ✅ |
| 混合好坏行 | 好行进入 records，坏行行号正确 | ✅ |
| 空文件 / 仅表头 | 返回空列表，无错误 | ✅ |
| 短行（字段缺失） | 记入 ParseError，原因标注 `missing-field` | ✅ |

### 3.2 单条记录校验规则（REQ-002）

每条成功解析的记录将依次接受以下 5 条规则的校验。**任一规则不满足即记入异常清单**，同一条记录命中多条规则时逐条列出，行号保留。

| # | 规则 | 违规样例 | 异常标识 |
|---|------|----------|----------|
| 1 | `amount > 0` | 金额为 0、负数、非数字字符串 | `amount_not_positive` |
| 2 | `date` 不晚于当天、不早于 `--max-age-days`（默认 365 天）之前 | 未来日期、超过 365 天前、无效日期字符串、边界值（今天/365天前） | `date_out_of_range` |
| 3 | `category` ∈ {`travel`, `meal`, `office`, `other`} | 未知类别、空字符串 | `invalid_category` |
| 4 | `note` 去空白后非空 | 空字符串、纯空白字符、None | `empty_note` |
| 5 | `currency == CNY` | USD、空字符串 | `invalid_currency` |

#### 测试证据：26 项全覆盖

| 规则编号 | 覆盖的测试用例 | 结果 |
|----------|----------------|------|
| amount > 0 | 0、负数、字符串 | ✅ 26 passed |
| date 范围 | 未来日期、超过 365 天、无效字符串、边界（今天、365天前） | ✅ |
| category 集合 | 未知类别、空字符串 | ✅ |
| note 非空 | 空字符串、纯空白、None | ✅ |
| currency == CNY | USD、空字符串 | ✅ |
| 多条规则同时命中 | 逐条列出所有违规 | ✅ |
| 行号保留 | 错误信息包含原始行号 | ✅ |
| 空记录集 | 不报错，正常通过 | ✅ |

### 3.3 重复报销检测（REQ-003）

> ⏳ 本模块开发中，以下行为基于需求规格描述。

- **判定条件**：同一员工 + 同一类别 + 同一金额 + 同一日期 = 重复
- **作用范围**：仅限同一次导入批次内部
- **处理策略**：校验之后进行；同一批次内第一次出现保留为有效记录，第二次及之后出现的行标记为「重复」

#### 预期输出示例（开发完成后）

在 Markdown 报表的**重复清单**附录中：

```markdown
## 重复报销清单

| 行号 | 员工 | 类别 | 金额 | 日期 |
|------|------|------|------|------|
| 5    | 张三 | travel | 1250.00 | 2025-03-01 |
| 8    | 张三 | travel | 1250.00 | 2025-03-01 |
```

验收标准（REQ-003）：构造三连同报销记录，第一条约入汇总，后两条出现在重复清单。

### 3.4 类别月度限额校验（REQ-004）

> ⏳ 本模块开发中，以下行为基于需求规格描述。

#### 限额配置文件格式（JSON）

```json
{
  "travel": 5000.00,
  "meal": 2000.00,
  "office": 1000.00,
  "other": 500.00
}
```

- 键为类别名，值为该类别每月金额上限（元）
- 按 **员工 × 类别 × 月份** 聚合有效记录金额
- 超出上限的记录按时间顺序标记为「超限」，直至该员工该类别当月剩余额度用尽
- **未提供 `--config` 或配置中缺少某类别时**：该部分不做限额校验，报告中注明「未设限」

#### 预期输出示例（开发完成后）

在 Markdown 报表的**超限清单**附录中：

```markdown
## 超限报销清单

| 行号 | 员工 | 类别 | 金额 | 月份 | 当月累计 | 限额 |
|------|------|------|------|------|----------|------|
| 12   | 李四 | meal | 1500.00 | 2025-03 | 3500.00 | 2000.00 |
```

> **注意**：超限记录仍计入汇总报表的金额合计（假设 Q-003 已确认：原记录保留在汇总中，仅在超限清单单独列出）。

- 报表数字与手工核算一致
- 四个清单齐全
- 无任何清单时显示「无」

## 四、常见问题 FAQ

### Q1：CSV 文件中出现坏行会怎样？

解析阶段会将坏行记入**解析错误清单**，包含行号与具体原因（如 `missing-field`、`invalid-date`、`invalid-amount` 等），**不中断**其余行的处理。好行继续进入后续校验流程。

### Q2：如何处理 BOM 头的 UTF-8 CSV 文件？

工具自动识别并正确处理带 BOM 的 UTF-8 文件，表头解析不受影响。

###  Q3：金额精度如何保证？

所有金额计算内部使用 Python `Decimal` 类型，避免浮点误差。验收时会用累计 1000 次 0.01 与 0.1 类数据核对，确保分毫不差。

### Q4：日期范围如何计算？

- **上限**：执行命令时的系统日期（服务器本地时区）
- **下限**：`--max-age-days` 参数指定天数之前（默认 365 天）
- `--max-age-days 0` 时，仅接受当天的记录

### Q5：超限的记录是否计入汇总金额？

是。超限记录仍计入三维汇总的有效金额合计，仅在**超限清单**中单独列出（假设 Q-003 已确认）。

### Q6：没有提供 `--config` 参数时会怎样？

工具不会对任何类别做限额校验，并在报告中注明「未设限」。

### Q7：退出码为 1 时如何判断是哪种问题？

查看输出的 Markdown 报表中的四个清单（解析错误清单、异常清单、重复清单、超限清单），每个清单均有行号与原因说明。

### Q8：工具是否支持网络访问？

不支持。工具完全离线运行，不访问任何网络资源。

### Q9：如何验证工具已正确安装？

```bash
cd workspace/expense-reporter
python -m pytest tests/ -v
```

预期结果：`40 passed in 0.06s`（CSV 解析）+ `26 passed in 0.04s`（记录校验）。
