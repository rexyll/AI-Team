## 一、项目概述

### 1.1 项目背景

行政部每月需人工核对员工提交的报销记录 CSV，工作包括查金额合法性、查重复报销、对照类别月度限额，再手工汇总成报表，耗时且易出错。本项目交付一个纯标准库实现的命令行工具 `expense_reporter`，自动完成校验、去重、限额比对与汇总报表输出。

### 1.2 目标用户

- **行政专员**：批量导入报销记录，得到异常清单与汇总报表。
- **财务复核人员**：依据报表与异常清单做人工复核。

### 1.3 交付物

交付物必须放置在 `workspace/expense-reporter/` 目录下，包含：
- 源码包
- 自动化测试
- README.md 使用文档

### 1.4 范围外

图形界面、多币种、Excel 输入、与报销系统集成、数据库持久化。

### REQ-001 CSV 读取与解析（必须）

**描述**：读取 UTF-8 编码（带或不带 BOM）的报销记录 CSV，必需列依次为：date、employee、category、amount、currency、note。
- date 格式为 YYYY-MM-DD
- amount 为两位小数的金额字符串
- currency 固定为 CNY
- 缺少必需列或某行字段数不符时，把该行记入解析错误清单（含行号与原因），不中断其余行的处理

**测试证据**：40 项测试全覆盖，包含好行解析、BOM 处理、多余列忽略、坏日期/坏金额/坏币种各自报 ParseError、混合好坏行、空文件/仅表头、短行解析、从文件路径解析。测试结果：40 passed in 0.06s。

### REQ-002 单条记录校验规则（必须）

**描述**：每条有效解析的记录依次校验：
1. amount 大于 0
2. date 不晚于当天，且不早于 --max-age-days 参数指定天数之前（默认 365）
3. category 属于允许集合 travel、meal、office、other
4. note 非空（去空白后）
5. currency 为 CNY

任何一条不满足即记入异常清单，注明行号、违反的规则与原始字段值。同一条记录命中多条规则时逐条列出。

**测试证据**：26 条测试用例均通过，覆盖所有 5 条规则边界（金额 0/负数/字符串、未来日期/超过 365 天/无效字符串/边界日期、未知类别/空字符串、空字符串/纯空白/None、USD/空字符串）、多条规则同时命中、行号保留、空记录集。测试结果：26 passed in 0.04s（pytest）/ 26 tests in 0.002s（unittest）。

### REQ-003 重复报销检测（必须）

**描述**：同一员工、同一类别、同一金额、同一日期的记录视为重复；同一批次内第二次及之后出现的行标记为「重复」，第一次出现保留为有效。重复检测在校验之后进行，仅针对未被判定为异常的记录。

**实现状态**：阻塞。

### REQ-004 类别月度限额校验（必须）

**描述**：限额配置为 JSON 文件，键为类别名，值为该类别每月金额上限（元）。按员工×类别×月份聚合有效记录金额，超出上限的记录按时间顺序标记为「超限」，直至该员工该类别当月剩余额度用尽。
- 未提供 --config 或配置中缺少某类别时，该部分不做限额校验，并在报告中注明「未设限」

**实现状态**：阻塞。

### REQ-005 Markdown 汇总报表（必须）

**描述**：输出人类可读的 Markdown 报表，包含：
1. 报表头：统计口径说明、生成时间、输入文件名、总行数
2. 三个汇总维度：按员工、按类别、按月份的有效金额合计与笔数
3. 明细附录：解析错误清单、异常清单、重复清单、超限清单，均含行号
4. 金额一律为两位小数

**实现状态**：阻塞。

### REQ-006 JSON 机器可读输出（应该）

**描述**：--json 参数指定输出路径时，写出 JSON 文件，含 summary（三维合计）、anomalies、duplicates、over_limit、parse_errors 五个键。所有金额以字符串表示（两位小数），禁止以浮点数表示。

**实现状态**：阻塞。

### REQ-007 命令行接口（必须）

**描述**：调用形式：`python -m expense_reporter input.csv --config limits.json --report report.md --json report.json --max-age-days 365`
- --config、--json、--max-age-days 均可省略
- 退出码契约：
  - 0：正常完成且无任何异常记录
  - 1：完成处理但存在解析错误、异常、重复或超限记录
  - 2：输入错误（输入文件不存在、必需列缺失、参数非法）

**实现状态**：阻塞。

### REQ-008 处理性能（应该）

## 五、假设与约束

### 已确认约束（来自客户需求）

1. **重复检测范围**：仅限同一次导入批次内部，不与历史文件比对【客户已确认】
2. **异常记录定义**：命中 REQ-002 任一规则或解析失败的行；重复与超限不算异常，各自独立成清单【客户已确认】
3. **退出码语义**：存在重复或超限但无异常与解析错误时，退出码同样为 1，财务人员据此人工复核【客户已确认】
4. **优先级含义**：必须项（REQ-001 至 REQ-005、REQ-007、REQ-009）为验收前提；应该项（REQ-006、REQ-008、REQ-010）允许在时间紧张时降级，但需在交付说明中注明未完成项【客户已确认】
5. **金额精度**：所有输入输出金额均为两位小数字符串；内部聚合必须使用 Decimal，验收时会用累计 1000 次 0.01 与 0.1 类数据核对分毫不差【客户已确认】
6. **冲突解决**：交付验收以本文与需求说明书冲突时，以需求说明书为准【客户已确认】

### 【假设】需进一步澄清的内容

1. 【假设】"当天"指执行命令时的系统日期，使用时区为服务器本地时区
2. 【假设】CSV 中多余列（除必需列外的列）直接忽略，不参与校验
3. 【假设】报表中的"按月份"维度按日期字段的 YYYY-MM 分组
4. 【假设】超限记录的标记方式是追加状态标识，原记录仍计入汇总，仅在超限清单中单独列出
