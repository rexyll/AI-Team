

# expense-reporter 用户手册

**版本**：v1.0.0（草案）  
**适用对象**：行政专员、财务复核人员  
**交付路径**：`workspace/expense-reporter/`

---

## 一、功能简介

`expense_reporter` 是一个用于批量处理员工费用报销记录的命令行工具，帮助行政与财务部门自动完成以下工作：

| 功能 | 说明 |
|------|------|
| CSV 解析（REQ-001） | 读取 UTF-8 编码的报销记录 CSV，自动识别表头，容错处理坏行 |
| 单条记录校验（REQ-002） | 对每条记录校验金额、日期、类别、备注、货币五类规则 |
| 重复报销检测（REQ-003） | 同一批次内相同员工/类别/金额/日期的记录，首次保留，后续标记为重复 |
| 类别月度限额校验（REQ-004） | 按员工×类别×月份聚合，超限记录标记为「超限」 |
| Markdown 汇总报表（REQ-005） | 输出含统计摘要与四个明细清单的 Markdown 文件 |
| JSON 机器可读输出（REQ-006） | 可选输出结构化 JSON，便于下游系统消费 |

---

## 二、快速上手

### 2.1 环境要求

- Python 3.8 或以上版本（仅使用标准库，无第三方依赖）
- 任意 Unix-like 终端或 Windows PowerShell/CMD

### 2.2 基本用法

```bash
python -m expense_reporter input.csv --report report.md
```

执行后，工具将生成 `report.md`，包含本次处理的统计汇总与异常清单。

### 2.3 完整参数说明

| 参数 | 必需 | 默认值 | 说明 |
|------|------|--------|------|
| `input.csv` | 是 | — | 输入的 CSV 文件路径（UTF-8 编码） |
| `--config <file>` | 否 | — | 限额配置 JSON 文件，格式见第 4.2 节 |
| `--report <file>` | 否 | `report.md` | Markdown 报表输出路径 |
| `--json <file>` | 否 | — | JSON 机器可读输出路径（REQ-006） |
| `--max-age-days <n>` | 否 | 365 | 校验日期时允许的最早天数（REQ-002） |

### 2.4 退出码说明

| 退出码 | 含义 |
|--------|------|
| 0 | 处理完成，无任何异常/解析错误/重复/超限记录 |
| 1 | 处理完成，但存在异常、解析错误、重复或超限记录 |
| 2 | 输入错误（文件不存在、必需列缺失、参数非法） |

## 三、操作步骤与示例

### 3.1 CSV 输入格式（REQ-001）

CSV 文件须满足以下规范：

- 编码：UTF-8（支持带 BOM）
- 表头（第一行）：`date,employee,category,amount,currency,note`
- 多余列将被忽略，缺少必需列的行记入解析错误清单

**示例 CSV 内容：**

```csv
date,employee,category,amount,currency,note
2024-03-01,张三,travel,1200.00,CNY,北京出差机票
2024-03-01,张三,meal,85.50,CNY,客户招待午餐
2024-03-02,李四,office,320.00,CNY,办公用品采购
2024-03-01,张三,travel,1200.00,CNY,北京出差机票
```

> 注意：第 4 行为第 1 行的重复记录（同员工/类别/金额/日期）。

### 3.2 限额配置文件格式（REQ-004）

限额配置为 JSON 文件，键为类别名，值为该类别每月金额上限（单位：元）：

```json
{
  "travel": 5000.00,
  "meal": 2000.00,
  "office": 1000.00,
  "other": 500.00
}
```

若未提供 `--config`，或未配置某类别，则该类别不做限额校验，报告中注明「未设限」。

### 3.3 运行示例

**场景：处理含重复记录的 CSV，并指定限额配置**

```bash
python -m expense_reporter \
  expense_data.csv \
  --config limits.json \
  --report report.md \
  --json report.json
```

**预期 Markdown 报表结构：**

## 四、校验规则详解（REQ-002）

每条有效解析的记录依次执行以下五项校验：

| 序号 | 规则 | 说明 | 违规示例 |
|------|------|------|----------|
| 1 | 金额 > 0 | `amount` 必须为正数 | 0.00、-50.00 |
| 2 | 日期合法 | 不晚于当天，不早于 `--max-age-days` 天前 | 未来日期、超过 365 天的旧记录 |
| 3 | 类别有效 | 仅允许：`travel`、`meal`、`office`、`other` | `entertainment`、空值 |
| 4 | 备注非空 | 去除首尾空白后不得为空字符串 | `""`、`"   "` |
| 5 | 货币为 CNY | 仅支持人民币 | `USD`、`EUR` |

**命中多条规则时，逐条列出**。例如一条记录同时违反「金额 ≤ 0」和「类别无效」，则异常清单中出现两行，分别说明违反的规则。

## 五、重复报销检测（REQ-003）

- **判定条件**：同一员工 + 同一类别 + 同一金额 + 同一日期
- **范围**：仅限本次导入批次内部，不与历史文件比对
- **处理逻辑**：按行顺序扫描，同一组合首次出现视为有效记录，后续出现标记为「重复」

**示例**：

```csv
date,employee,category,amount,currency,note
2024-03-01,张三,travel,1200.00,CNY,机票
2024-03-01,张三,travel,1200.00,CNY,机票重复提交
```

第二条记录在重复清单中体现，第一条进入有效汇总。

## 六、类别月度限额校验（REQ-004）

### 6.1 校验逻辑

1. 按「员工 × 类别 × 月份」聚合所有有效记录（通过 REQ-002 校验且非重复）
2. 若配置文件中存在该类别限额，则按时间顺序累加金额，超出上限后标记为「超限」
3. 剩余额度计算精确到分，无浮点误差（使用 `Decimal`）

### 6.2 示例

假设限额配置为 `travel: 5000.00`，员工张三 2024 年 3 月有以下记录：

| 日期 | 金额 | 累计 | 是否超限 |
|------|------|------|----------|
| 03-01 | 2000.00 | 2000.00 | 否 |
| 03-05 | 3500.00 | 5500.00 | 是（超出 5000.00） |
| 03-10 | 1000.00 | — | 是 |

第二条记录中，第 5000.00 元额度用完，超出部分标记为超限。

### 6.3 未配置限额时的行为

若未提供 `--config`，或配置中缺少某类别，报告中对应维度注明「未设限」，该类别不做超限判断。

## 七、报表输出说明（REQ-005 / REQ-006）

### 7.1 Markdown 报表

报表包含四个固定章节：

1. **报表头**：统计口径、生成时间、输入文件名、总行数
2. **汇总统计**：按员工、按类别、按月份三个维度的有效金额合计与笔数
3. **解析错误清单**：原始 CSV 中行数不符或缺少必需列的记录
4. **异常/重复/超限清单**：各自独立成表，均含行号

**无任何清单时，对应章节显示「无」。**

### 7.2 JSON 输出

使用 `--json report.json` 时，输出结构如下：

```json
{
  "summary": {
    "by_employee": [
      {"employee": "张三", "total": "1285.50", "count": 2}
    ],
    "by_category": [
      {"category": "travel", "total": "1200.00", "count": 1}
    ],
    "by_month": [
      {"month": "2024-03", "total": "1605.50", "count": 3}
    ]
  },
  "anomalies": [],
  "duplicates": [
    {"row": 4, "employee": "张三", "category": "travel", "amount": "1200.00", "date": "2024-03-01"}
  ],
  "over_limit": [],
  "parse_errors": []
}
```

> **金额字段始终为字符串类型**，避免浮点精度问题。

## 八、常见问题 FAQ

### Q1：CSV 文件中有空行或格式错误的行会报错吗？

不会。工具会将格式不匹配的行（字段数不符、必需列缺失等）记入「解析错误清单」，其余行继续正常处理。

### Q2：为什么退出码是 1，但报表中没有任何异常？

退出码 1 表示「完成处理但存在异常、解析错误、重复或超限记录」。只要这四个清单中任意一个非空，退出码即为 1。

### Q3：日期格式有何要求？

支持 `YYYY-MM-DD` 格式（如 `2024-03-01`），其他格式将记入解析错误清单。

### Q4：金额精度如何保证？

工具内部使用 `Decimal` 进行所有金额计算，避免了 `float` 的精度丢失问题。输入输出的金额均格式化为两位小数字符串。

### Q5：能否处理超大文件？

根据性能验收要求（REQ-008），10,000 行合法记录应在 30 秒内完成全部校验、去重与报表输出。实际性能取决于硬件环境，建议在合理文件大小范围内运行。

### Q6：如何指定其他货币？

目前仅支持 `CNY`。若记录中货币字段不为 `CNY`，该记录将被记入异常清单，理由为「货币非 CNY」。

### Q7：重复报销是否跨批次识别？

否。重复检测范围仅限于同一次导入批次内部，不与历史文件比对（A-02）。
