

# 用户手册 — expense_reporter

## 一、产品简介

`expense_reporter` 是一款报销单校验与汇总命令行工具，专为行政专员与财务复核人员设计。

**核心能力**

- **CSV 解析**：读取 UTF-8 编码的报销记录（自动处理 BOM），坏行自动记入解析错误清单，不中断整体流程。
- **记录校验**：逐项检查金额、日期范围、费用类别、备注内容与币种，命中多条规则时逐条列出。
- **重复检测**：同一员工 × 类别 × 金额 × 日期的记录在批次内去重，首次出现保留为有效，后续重复进入重复清单。
- **限额比对**：按「员工 × 类别 × 月份」聚合有效金额，超过限额配置后继续标记为「超限」。
- **报表输出**：生成可读的 Markdown 汇总报表；通过 `--json` 可选输出机器可读 JSON。

**技术约束**：纯 Python 标准库实现，无任何第三方依赖；金额统一使用 `Decimal` 计算，杜绝浮点累加误差。

## 二、快速上手

### 2.1 环境准备

- Python 3.9 及以上
- 无额外依赖安装需求

### 2.2 命令模板

```bash
python -m expense_reporter <输入CSV> [选项]
```

### 2.3 最小运行示例

准备以下两个文件：

**`expenses.csv`**（UTF-8 编码，带或不带 BOM 均可）

| date | employee | category | amount | currency | note |
|------|----------|----------|--------|----------|------|
| 2025-01-15 | 张三 | travel | 1200.00 | CNY | 高铁票 |
| 2025-01-15 | 张三 | travel | 1200.00 | CNY | 高铁票 |
| 2025-01-16 | 李四 | meal | 85.50 | CNY | 业务招待 |

**运行：**

```bash
cd workspace/expense-reporter
python -m expense_reporter expenses.csv --report report.md
```

**退出码 1**（存在重复记录），生成 Markdown 报表 `report.md`，内容包含有效金额汇总、重复清单、各维度明细。

### 2.4 查看帮助

```bash
python -m expense_reporter --help
```

## 三、输入文件格式

### 3.1 CSV 文件规范

**文件编码**：UTF-8（自动兼容带 BOM）

**首行为表头**，必需列（按此顺序）：

| 列名 | 说明 | 示例 |
|------|------|------|
| `date` | 费用发生日期，格式 YYYY-MM-DD | `2025-01-15` |
| `employee` | 员工姓名 | `张三` |
| `category` | 费用类别：`travel` / `meal` / `office` / `other` | `travel` |
| `amount` | 金额，正数，两位小数 | `1200.00` |
| `currency` | 币种，必须为 `CNY` | `CNY` |
| `note` | 备注，去空白后非空 | `高铁票` |

**允许**：多余列被忽略；**禁止**：缺少必需列，或某行字段数不符（该整行记入解析错误清单，不影响其他行处理）。

### 3.2 限额配置文件（JSON）

通过 `--config` 指定，键为类别名，值为该类别每月金额上限（元）：

```json
{
  "travel": 3000.00,
  "meal": 500.00,
  "office": 1000.00,
  "other": 200.00
}
```

**注意**：未提供 `--config` 或配置中缺少某类别时，对应部分不做限额校验，报告中注明「未设限」。

## 四、命令参数说明

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `input`（位置参数） | 路径 | — | 输入 CSV 文件路径（必需） |
| `--config` | 路径 | — | 限额配置文件路径（可选） |
| `--report` | 路径 | — | Markdown 报表输出路径（可选） |
| `--json` | 路径 | — | JSON 机器可读输出路径（可选） |
| `--max-age-days` | 整数 | `365` | 允许的最早日期范围（默认一年内） |

## 五、各功能详细说明

### 5.1 CSV 解析与坏行处理（REQ-001）

**行为**：

- 文件不存在 → 退出码 `2`，报错提示。
- 缺少必需列 → 退出码 `2`，列出缺失列名。
- 单行字段数不符或无法解析 → 该行记入「解析错误清单」（含行号与原因），其余行继续处理。

**示例（坏行场景）**

```
date,employee,category,amount,currency,note
2025-01-15,张三,travel,1200.00,CNY,高铁票
2025-01-16,李四,meal   <-- 此行字段不足，缺 currency 与 note
2025-01-17,王五,office,300.00,CNY,办公用品
```

解析错误清单将记录第 3 行的原因（字段数不符），第 2 行和第 4 行正常进入后续校验。

### 5.2 单条记录校验（REQ-002）

**校验规则**（依次执行，命中多条均逐条记录）：

| # | 规则 | 违反示例 |
|---|------|----------|
| ① | `amount > 0` | `0`、`-50.00` |
| ② | `date` 不早于 `--max-age-days` 天前且不晚于当天 | `2023-01-01`（当窗口为 365 天时超龄） |
| ③ | `category ∈ {travel, meal, office, other}` | `entertainment` |
| ④ | `note` 去空白后非空 | ` `（纯空格） |
| ⑤ | `currency == CNY` | `USD` |

异常清单中每条记录列出：行号、违反规则序号及原始字段值。

### 5.3 重复报销检测（REQ-003）

**判定标准**：同一员工 + 同一类别 + 同一金额 + 同一日期的记录视为重复。

**行为**：
- 仅在同一次导入批次内检测，不与历史文件比对。
- 仅在未被判定为异常的记录中检测。
- 同组中第一次出现保留为有效，第二次及之后标记为「重复」，进入重复清单。

**示例**：以下三行构成重复链

| 行号 | employee | category | amount | date | 结果 |
|------|----------|----------|--------|------|------|
| 2 | 张三 | travel | 1200.00 | 2025-01-15 | 有效（首次） |
| 3 | 张三 | travel | 1200.00 | 2025-01-15 | 重复 |
| 4 | 张三 | travel | 1200.00 | 2025-01-15 | 重复 |

### 5.4 类别月度限额校验（REQ-004）

**计算粒度**：按「员工 × 类别 × 月份」独立计算，跨月不累计。

**行为**：
- 按时间顺序累加有效记录金额。
- 超出当月上限后，后续记录标记为「超限」，直至该维度剩余额度用尽。
- 未提供 `--config` 或某类别未配置时，该部分不做限额校验，报告中注明「未设限」。

**示例**：限额配置 `{"travel": 3000.00}`，员工张三 2025-01 发生三笔 travel：

| 行号 | amount | 累计 | 是否超限 |
|------|--------|------|----------|
| 5 | 1200.00 | 1200.00 | 否 |
| 6 | 1500.00 | 2700.00 | 否 |
| 7 | 600.00 | 3300.00 | 是（超限 300.00） |

### 5.5 Markdown 汇总报表（REQ-005）

报表结构固定，包含四大部分：

**① 报表头**
- 统计口径说明
- 生成时间
- 输入文件名
- 总行数

**② 三个汇总维度**（按员工、按类别、按月份）的有效金额合计与笔数

**③ 明细附录**（四个清单，均含行号）
- 解析错误清单
- 异常清单
- 重复清单
- 超限清单

**④ 无清单时显示「无」**

金额一律保留两位小数。

### 5.6 JSON 机器可读输出（REQ-006）

通过 `--json report.json` 生成，结构与 Markdown 报表对应：

```json
{
  "summary": {
    "by_employee": { ... },
    "by_category": { ... },
    "by_month": { ... }
  },
  "anomalies": [ ... ],
  "duplicates": [ ... ],
  "over_limit": [ ... ],
  "parse_errors": [ ... ]
}
```

所有金额字段均为字符串（两位小数），不出现浮点数。

## 六、退出码说明

| 退出码 | 含义 |
|--------|------|
| `0` | 正常完成，且无任何异常（解析错误、异常、重复、超限均为空） |
| `1` | 完成处理，但存在解析错误、异常、重复或超限记录 |
| `2` | 输入错误（输入文件不存在、必需列缺失、参数非法） |

**注意**：仅存在重复或超限时，同样返回退出码 `1`。

## 七、常见问题 FAQ

### Q1：CSV 文件中出现乱码怎么办？
A：请确保 CSV 文件以 UTF-8 编码保存。工具自动兼容带 BOM 的 UTF-8 文件。

### Q2：某行数据有缺失字段，会影响其他行吗？
A：不会。单行解析失败仅将该行记入解析错误清单，其余行继续正常处理。

### Q3：限额配置文件中没有某个类别（如 `other`），会报错吗？
A：不会。缺少类别时该类别不做限额校验，报告中注明「未设限」。

### Q4：重复记录会被计入汇总吗？
A：不会。重复清单中的记录不参与有效金额汇总。

### Q5：超限记录是否影响汇总？
A：超限记录仍作为有效记录参与汇总，仅在超限清单中单独列出。

### Q6：退出码为 1，是否意味着处理失败？
A：不是。退出码 `1` 表示处理已完成，但发现了需要人工关注的问题（异常、重复、超限或解析错误）。

### Q7：如何处理大批量文件（如上万条记录）？
A：工具按设计支持万行规模在 30 秒内完成。建议配合 `--report` 与 `--json` 同时输出，便于后续核查。

### Q8：能否与其他历史报销文件做跨批次重复检测？
A：不能。重复检测仅限同一次导入批次内部，不与历史文件比对。如需跨批次去重，请合并所有记录后一次性导入。

### Q9：金额为什么不用浮点数？
A：工具内部统一使用 `Decimal` 计算，杜绝 `0.1 + 0.2 = 0.30000000000000004` 类浮点累加误差，确保金额分毫不差。

### Q10：如何调试异常详情？
A：查看生成的 Markdown 报表「异常清单」部分，每条记录会注明行号、违反规则及原始字段值；配合 `--json` 输出可在程序中逐条分析。
