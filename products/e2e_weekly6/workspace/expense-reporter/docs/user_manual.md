## 一、功能简介

**报销单校验与汇总工具**（`expense_reporter`）是一个命令行工具，用于对员工报销 CSV 记录进行自动校验与汇总。工具核心能力包括：

| 功能 | 说明 |
|------|------|
| CSV 解析 | 读取 UTF-8 编码的报销记录 CSV（支持带/不带 BOM），坏行自动记入解析错误清单，不中断处理 |
| 记录校验 | 按规则检查金额合法性、日期范围、类别、备注非空、币种（仅 CNY） |
| 重复检测 | 同一员工 × 类别 × 金额 × 日期的重复记录，仅同批次内去重 |
| 限额校验 | 对照 JSON 限额配置，按「员工 × 类别 × 月份」独立计算，超限额记录标记为「超限」 |
| Markdown 报表 | 生成含统计摘要 + 四个明细清单（解析错误、异常、重复、超限）的可读报表 |
| JSON 输出 | 可选，供自动化流程调用，金额字段为两位小数字符串 |

**技术约束**：仅使用 Python 标准库；金额计算使用 `Decimal`，禁止 `float`；不访问网络；输出全部为中文。

## 二、快速上手

### 2.1 前置条件

- Python 3.8+
- 报销记录 CSV 文件（见附录 A 格式说明）
- （可选）限额配置文件 JSON（见附录 B）

### 2.2 基本命令

```bash
python -m expense_reporter input.csv --report report.md
```

运行后会在当前目录生成 `report.md`，包含本次处理的汇总信息与清单。

### 2.3 带限额配置的完整示例

```bash
python -m expense_reporter input.csv \
  --config limits.json \
  --report report.md \
  --json report.json \
  --max-age-days 365
```

- `--report report.md`：生成 Markdown 汇总报表
- `--json report.json`：生成机器可读 JSON 文件
- `--config limits.json`：限额配置文件路径（省略则不对类别做限额校验）
- `--max-age-days 365`：日期有效范围（默认 365 天，可省略）

### 2.4 查看处理结果

处理完成后，工具以**退出码**告知结果：

| 退出码 | 含义 |
|--------|------|
| `0` | 处理完成，无任何异常记录 |
| `1` | 处理完成，但存在解析错误、异常、重复或超限记录 |
| `2` | 输入错误（文件不存在、列缺失、参数非法） |

在 Shell 中可通过 `$?` 或 `echo $?` 查看退出码。

## 三、功能详细说明

### 3.1 CSV 输入格式

输入文件须为 **UTF-8 编码**的 CSV，表头必需列依次为：

```
date,employee,category,amount,currency,note
```

| 字段 | 说明 | 示例 |
|------|------|------|
| `date` | 报销日期，格式 `YYYY-MM-DD` | `2025-06-15` |
| `employee` | 员工姓名 | `张三` |
| `category` | 费用类别，须为 `travel` / `meal` / `office` / `other` 之一 | `travel` |
| `amount` | 金额，须为两位小数数字 | `128.50` |
| `currency` | 币种，须为 `CNY` | `CNY` |
| `note` | 备注，去空白后非空 | `出差高铁票` |

**注意**：
- 多余列会被忽略；
- 缺列或字段数不符的行记入「解析错误清单」，不阻断处理；
- 表头顺序固定，不支持乱序或自定义列名。

#### 示例 CSV

```csv
date,employee,category,amount,currency,note
2025-06-01,张三,travel,350.00,CNY,北京到上海高铁
2025-06-01,张三,meal,68.50,CNY,午餐
2025-06-02,李四,office,120.00,CNY,打印纸
2025-06-02,李四,office,120.00,CNY,打印纸
```

---

### 3.2 记录校验规则（REQ-002）

每条有效解析的记录依次校验以下 5 条规则，任一条不满足即记入**异常清单**，注明行号、违反规则与原始字段值：

| # | 规则 | 说明 |
|---|------|------|
| 1 | `amount > 0` | 金额必须为正数 |
| 2 | 日期范围 | 不晚于当天，不早于 `--max-age-days` 天前（默认 365 天） |
| 3 | 类别合法 | 须为 `travel`、`meal`、`office` 或 `other` 之一 |
| 4 | 备注非空 | `note` 去空白后不能为空 |
| 5 | 币种为 CNY | `currency` 必须等于 `CNY` |

> **重要**：异常记录不会进入重复检测或限额校验，各自独立成单。

---

### 3.3 重复报销检测（REQ-003）

**判定条件**：同一员工 × 同一类别 × 同一金额 × 同一日期 视为重复。

**检测逻辑**：
- 在同一批次内，首次出现的记录保留为有效记录，纳入汇总；
- 第二次及之后出现的同类记录标记为「重复」，写入重复清单；
- 重复检测仅针对未被判定为异常的有效记录。

**示例**：第三部分示例 CSV 中第 3 行和第 4 行（李四、office、120.00、2025-06-02）互为重复，第 4 行将出现在重复清单中。

---

### 3.4 类别月度限额校验（REQ-004）

**限额配置格式**（JSON）：

```json
{
  "travel": 5000.00,
  "meal": 2000.00,
  "office": 3000.00,
  "other": 1000.00
}
```

- 键为类别名，值为该类别每月金额上限（元）；
- 限额按「员工 × 类别 × 月份」独立计算，跨月不累计；
- 超出上限的记录按时间顺序标记为「超限」，直至当月剩余额度用尽。

**无配置运行时**：若省略 `--config` 或配置中缺少某类别，该类别不做限额校验，报告中注明「未设限」。

---

### 3.5 输出格式说明

#### Markdown 报表（REQ-005）

报表包含以下内容：

1. **报表头**：统计口径说明、生成时间、输入文件名、总行数
2. **汇总维度**：
   - 按员工汇总（有效金额合计与笔数）
   - 按类别汇总（有效金额合计与笔数）
   - 按月份汇总（有效金额合计与笔数）
3. **明细附录**：
   - 解析错误清单（含行号与原因）
   - 异常清单（含行号、违规规则与原始字段值）
   - 重复清单（含行号）
   - 超限清单（含行号与剩余额度）
4. 任一清单为空时显示「无」；所有金额为两位小数。

#### JSON 输出（REQ-006）

指定 `--json report.json` 时生成，结构如下：

```json
{
  "summary": {
    "by_employee": { ... },
    "by_category": { ... },
    "by_month": { ... }
  },
  "anomalies": [...],
  "duplicates": [...],
  "over_limit": [...],
  "parse_errors": [...]
}
```

- 所有金额字段均为**两位小数字符串**，不使用浮点数。

## 六、常见问题 FAQ

### Q1：解析错误清单中，"必需列缺失"是指什么？

指 CSV **表头**缺少 `date`、`employee`、`category`、`amount`、`currency`、`note` 六个必需列中的任何一个，或某数据行字段数与表头列数不符。两者均会记入解析错误清单，含行号与具体原因。

### Q2：`date` 字段"不晚于当天"的"当天"是指什么时候？

指工具**运行时刻的日期**（即执行命令当天的日期），不固定。

### Q3：限额配置中缺少某个类别，会怎样处理？

该类别不做限额校验，报告中相应汇总部分注明「未设限」。

### Q4：退出码 1 是否包含重复或超限记录？

是的。退出码 1 表示「处理完成但存在异常记录」，异常记录包括：解析错误、校验异常、重复、超限，任一情况发生均返回 1。

### Q5：为什么金额使用字符串而非数字？

内部聚合使用 `Decimal` 类型保证精度（如 `0.1 + 0.2` 类累加误差不会出现），输出时为两位小数字符串，便于机器解析且避免浮点精度问题。

### Q6：重复检测会跨文件比对吗？

不会。重复检测范围仅限**同一次导入批次内部**，不与历史文件比对。

### Q7：如何处理含 BOM 的 UTF-8 文件？

工具自动识别并剥离 BOM，无需手动处理。

### Q8：金额字段的格式要求是什么？

须为两位小数的数字（如 `128.50`），一位小数（如 `128.5`）或不带小数（如 `128`）均会被记为解析错误。
