## 一、项目概述

### 1.1 项目背景

行政部每月需人工核对员工提交的报销记录 CSV，包括查金额合法性、查重复报销、对照类别月度限额，再手工汇总成报表，费时且易错。本项目交付一个纯 Python 标准库实现的命令行工具，自动完成校验、去重、限额比对与汇总报表输出。

> 来源：需求规格草案「一、项目概述」

### 1.2 项目目标

| 目标项 | 说明 |
|--------|------|
| 自动化校验 | 自动完成金额合法性、日期有效性、类别合法性、币种校验 |
| 重复检测 | 同批次内识别同一员工×类别×金额×日期的重复记录 |
| 限额控制 | 按员工×类别×月份聚合，比对月度限额配置 |
| 报表输出 | 生成人类可读的 Markdown 报表及可选的 JSON 机器可读输出 |
| 零依赖交付 | 仅使用 Python 标准库，不引入第三方依赖 |

> 来源：需求规格草案「一、项目概述」、项目规划摘要

### 1.3 目标用户

| 角色 | 主要操作 | 使用场景 |
|------|----------|----------|
| 行政专员 | 批量导入报销记录，得到异常清单与汇总报表 | 每月报销处理周期 |
| 财务复核人员 | 依据报表与异常清单做人工复核 | 财务审核流程 |

> 来源：需求规格草案「一、项目概述」

### 1.4 交付要求

交付物必须放置在 `workspace/expense-reporter/` 目录下，包含：
- 源码包（`src/expense_reporter/`）
- 自动化测试套件（`tests/`）
- README.md 使用文档

## 二、功能需求清单

### REQ-001（必须）CSV 读取与解析

**描述：**  
读取 UTF-8 编码（带或不带 BOM）的报销记录 CSV，必需列依次为：`date`、`employee`、`category`、`amount`、`currency`、`note`。`date` 格式为 YYYY-MM-DD；`amount` 为两位小数金额字符串；`currency` 固定为 CNY。缺少必需列或某行字段数不符时，把该行记入解析错误清单（含行号与原因），不中断其余行的处理。

**验收标准：**  
对含坏行的样例 CSV 运行后，坏行全部出现在解析错误清单中且行号正确，好行正常进入后续校验。

**优先级：** 必须（P0）  
**状态：** 待实现

---

### REQ-002（必须）单条记录校验规则

**描述：**  
每条有效解析的记录依次校验：
1. `amount` 大于 0
2. `date` 不晚于当天且不早于 `--max-age-days` 参数指定天数之前（默认 365）
3. `category` 属于允许集合：`travel`、`meal`、`office`、`other`
4. `note` 非空（去空白后）
5. `currency` 为 CNY

任何一条不满足即记入异常清单，注明行号、违反规则与原始字段值。同一条记录命中多条规则时逐条列出。

**验收标准：**  
构造覆盖每条规则的违规样例各至少一条，异常清单逐条命中且理由正确。

**优先级：** 必须（P0）  
**状态：** 待实现

---

### REQ-003（必须）重复报销检测

**描述：**  
同一员工、同一类别、同一金额、同一日期的记录视为重复；同一批次内第二次及之后出现的行标记为「重复」，第一次出现保留为有效。重复检测在校验之后进行，仅针对未被判定为异常的记录。仅限同一次导入批次内部比对，不与历史文件比对。

**验收标准：**  
构造三连同报销记录，输出中第一条约入汇总，后两条出现在重复清单。

**优先级：** 必须（P0）  
**状态：** 待实现

---

### REQ-004（必须）类别月度限额校验

**描述：**  
限额配置为 JSON 文件，键为类别名，值为该类别每月金额上限（元）。按员工×类别×月份聚合有效记录金额，超出上限的记录按时间顺序标记为「超限」，直至该员工该类别当月剩余额度用尽。未提供 `--config` 或配置中缺少某类别时，该部分不做限额校验，并在报告中注明「未设限」。

**验收标准：**  
构造跨两月的样例与限额配置，超限标记与剩余额度计算完全正确；无配置运行时报告出现未设限说明。

**优先级：** 必须（P0）  
**状态：** 待实现

---

### REQ-005（必须）Markdown 汇总报表

**描述：**  
输出人类可读的 Markdown 报表，包含：
1. **报表头：** 统计口径说明、生成时间、输入文件名、总行数
2. **三个汇总维度：** 按员工、按类别、按月份的有效金额合计与笔数
3. **明细附录：** 解析错误清单、异常清单、重复清单、超限清单，均含行号
4. **金额格式：** 一律为两位小数

**验收标准：**  
报表数字与手工核算一致；四个清单齐全；无任何清单时显示「无」。

**优先级：** 必须（P0）  
**状态：** 待实现

---

### REQ-006（应该）JSON 机器可读输出

**描述：**  
`--json` 参数指定输出路径时，写出 JSON 文件，含 `summary`（三维合计）、`anomalies`、`duplicates`、`over_limit`、`parse_errors` 五个键。所有金额以字符串表示（两位小数），禁止以浮点数表示。

**验收标准：**  
JSON 与 Markdown 报表数字完全一致；金额字段类型为字符串。

**优先级：** 应该（P1）  
**状态：** 待实现

---

### REQ-007（必须）命令行接口

**描述：**  
调用形式：
```bash
python -m expense_reporter input.csv --config limits.json --report report.md --json report.json --max-age-days 365
```

`--config`、`--json`、`--max-age-days` 均可省略。

**退出码契约：**
| 退出码 | 含义 |
|--------|------|
| 0 | 正常完成且无任何异常记录 |
| 1 | 完成处理但存在解析错误、异常、重复或超限记录 |
| 2 | 输入错误（输入文件不存在、必需列缺失、参数非法） |

**验收标准：**  
三种退出码场景各有自动化测试证据。

**优先级：** 必须（P0）  
**状态：** 待实现

---

10,000 行合法记录在 30 秒内完成全部校验、去重与报表输出。

**验收标准：**  
测试中生成 10,000 行 CSV，用计时器断言总耗时小于 30 秒。

**优先级：** 应该（P1）  
**状态：** 待实现

---

### REQ-009（必须）自动化测试

**描述：**  
测试覆盖：
- 每条校验规则的边界（金额 0 与负数、日期边界、类别外值、空 note）
- 重复链
- 跨月限额
- 坏行解析
- 三种退出码
- 金额 Decimal 精度（如 0.1+0.2 类累加误差不得出现）
- 测试全部离线运行，不依赖网络

**验收标准：**  
测试报告显示全部通过，且用例名可对应到上述场景。

**优先级：** 必须（P0）  
**状态：** 待实现

- 仅使用 Python 标准库，不引入第三方依赖

> 来源：需求规格草案「三、非功能需求」

> 来源：需求规格草案「三、非功能需求」

### 3.4 兼容性

- 仅支持 Python 标准库实现
- 不依赖数据库、图形界面、外部系统

> 来源：需求规格草案「三、非功能需求」

### 3.5 数据精度

- 金额计算一律使用 `Decimal`，禁止 `float` 聚合
- 所有输入输出金额均为两位小数字符串
- 验收时会用累计 1000 次 0.01 与 0.1 类数据核对分毫不差
