## 一、测试策略

### 1.1 测试范围

本次测试覆盖需求规格说明中的全部功能需求（REQ-001 至 REQ-010）及非功能需求（性能、兼容性、精度要求）。测试策略如下：

| 测试类型 | 覆盖范围 | 测试方法 |
|---------|---------|---------|
| 解析测试 | REQ-001 | 构造含坏行的样例 CSV，验证解析错误清单行号与原因正确 |
| 校验规则测试 | REQ-002 | 分别构造金额≤0、日期越界、类别非法、note 为空、currency 非 CNY 的样例，验证异常清单命中 |
| 重复检测测试 | REQ-003 | 构造三连同报销记录，验证第一条入汇总、后两条入重复清单 |
| 限额校验测试 | REQ-004 | 构造跨两月样例与限额配置，验证超限标记与剩余额度计算 |
| 报表生成测试 | REQ-005 | 验证 Markdown 报表数字与手工核算一致，四个清单齐全 |
| JSON 输出测试 | REQ-006 | 验证 JSON 与 Markdown 数字一致，金额字段为字符串类型 |
| CLI 接口测试 | REQ-007 | 验证三种退出码场景（0/1/2）均有对应自动化测试 |
| 性能测试 | REQ-008 | 生成 10,000 行合法 CSV，计时断言总耗时 < 30 秒 |
| 自动化测试 | REQ-009 | 验证全部用例通过，用例名可对应边界场景 |
| 文档验收 | REQ-010 | 验证 README 内容完整，示例可独立运行 |

### 1.2 测试层级

- **单元测试**：各模块独立功能（parser、validator、reporter）
- **集成测试**：CLI 入口与全流程串联
- **验收测试**：端到端场景验证
